# ADR 002: 表达式与语句的边界

## 状态

已接受（2026-07-31）

## 背景

Kore 声称"一切皆表达式"，但仍需明确：哪些构造的类型是 `void` 或 `never`，哪些构造只允许在特定位置出现，以及类型统一规则如何处理发散与弃值。本 ADR 固定这些边界，以保证类型检查器、语法分析器、IDE 工具链的行为一致。

关键问题：
1. `=` / `:=` / 复合赋值等副作用构造是否产出有意义的值？
2. 块、分支、循环、`defer`、`unsafe`、`asm` 各自的类型是什么？
3. 非 `void` 值在非末尾位置被忽略时，是警告还是错误？
4. `never` 类型如何参与类型统一？
5. `void` 值如何书写？

## 决策

### 原则

1. **一切皆表达式** — 所有构造都有类型。无意义的副作用构造类型为 `void`；发散构造类型为 `never`。没有独立的"语句"层。
2. **弃值显式化** — 非 `void` 值在非末尾位置被静默丢弃是编译错误，必须写 `_ = expr`。
3. **`never` 是底类型** — `never` 可以统一到任意类型，`never` 臂在类型统一中被忽略。
4. **赋值限位** — `=` 和复合赋值 `+=` 等只允许出现在块的直接子节点（语句顶层），其他位置是句法错误。

### 核心类型规则

#### 赋值与绑定

| 构造 | 类型 | 位置限制 |
|------|------|---------|
| `:=`（运行期绑定） | `void` | 块直接子节点 |
| `=`（赋值） | `void` | 块直接子节点（句法强制） |
| `+=` / `-=` 等复合赋值 | `void` | 块直接子节点（句法强制） |
| `a, b = b, a`（并行赋值） | `void` | 块直接子节点 |

`=` 不允许出现在子表达式位置，是句法错误而非类型错误。理由：防止 `? (a = b) =>` 类的误写，符合"可预测性优先"。

#### 控制流

| 构造 | 类型 | 备注 |
|------|------|------|
| `ret expr` | `never` | 函数返回，类型系统视为发散 |
| `ret`（无值） | `never` | 等价于 `ret void`，只在返回 `void` 的函数中合法 |
| `stop expr` | `never` | 携带值退出循环 |
| `stop`（无值） | `never` | 等价于 `stop void` |
| `skip` | `never` | 进入下一轮循环 |
| `jmp f(args)` | `never` | 保证尾调用 |
| `defer expr` | `void` | 挂起清理，不产出值 |

#### 块

```
Block(stmts[]) 的类型 = 最后一个表达式的类型
```

- `;` 是纯分隔符，**尾随 `;` 是语法错误**（不得用 `;` 丢弃块值）
- 丢弃块值必须显式：`{ f(); g(); void }` 或外层 `_ = { ... }`
- 块内编译期绑定 `::` 合法，作用域限于该块，顺序无关（两遍扫描）
- 空块 `{}` 类型为 `void`

#### 分支

| 形式 | 类型 | 穷尽要求 |
|------|------|---------|
| 守卫 `? cond => stmt` | `void` | 右侧只允许 `void` 或 `never` |
| 条件链（多布尔臂） | 臂类型（需有 `_`）或 `void`（无 `_`） | 无 `_` 时类型强制为 `void` |
| 联合匹配 `? expr is { }` | 各臂统一类型 | 编译期静态穷尽检查，缺变体是编译错误 |

类型统一规则：`never` 臂被忽略；其余臂类型必须相同。

#### 循环

| 形式 | 无 `stop` 时类型 | 有 `stop v` 时类型 |
|------|----------------|-----------------|
| 条件循环 `@ cond { }` | `void` | `T?`（`stop v` 提供 `T`，正常退出得 `nil`） |
| 范围循环 `@ range => x { }` | `void` | `T?` |
| 迭代循环 `@ iter => x { }` | `void` | `T?` |
| 无限循环 `@ { }` | `never` | `T`（必有 `stop v` 才能退出） |

#### 其他构造

| 构造 | 类型 | 备注 |
|------|------|------|
| `unsafe { expr }` | 与 `expr` 相同 | 权限边界，不改变类型 |
| `asm { ... }` | 显式标注（`: Type`）；无标注默认 `void` | 支持 `never` 标注表示发散 |
| `\x => body`（闭包） | 从上下文推断；无上下文则要求显式标注 | 无法推断时 `\(x i32) i32 => ...` |
| `expr \|> f`（管道） | `f` 的返回类型 | 左结合，优先级低于算术/比较 |

### 弃值规则

非 `void` 值在非末尾位置被忽略 → **编译错误**。

```kore
-- 错误：pop() 返回 T?，值被丢弃
v.pop()

-- 正确：显式丢弃
_ = v.pop()

-- 正确：绑定使用
x := v.pop()
```

此规则对普通函数调用与方法调用一视同仁，不设例外，不需要 `#must_use` 标注机制。

### `void` 值的书写

`void` 既是类型也是唯一值的字面量：

```kore
f :: () void => void     -- 显式返回 void 值
g :: () void => {}       -- 空块，类型为 void，等价
h :: () void => ret      -- ret 不带值等价于 ret void
i :: () void => ()       -- 零元组，等价
```

`void`、`{}`、`()` 三种写法并存，语义唯一。

> **被 ADR 006 (D16) 修订**：本节原写「不引入 `()` 作为 unit 值（避免与函数调用语法混淆）」。ADR 006 D16 把 `()` 定为零元组即 `void` 的值，理由是元组元数需要连续（`()` 零元、`(x,)` 一元、`(x, y)` 二元），否则零元组要么无表示、要么成为第二个单位类型。所谓的混淆不存在：`f()` 的括号跟在被调用者之后，`()` 出现在无被调用者的表达式位置，解析器凭前趋记号即可区分。

### `::` 上下文中的表达式

编译期绑定 `::` 的右侧遵循与运行期完全相同的表达式规则，区别仅是求值时机（编译器内置求值器执行）。允许 `:=` 局部绑定、`?`/`@`、函数调用等全部构造。

### 并行赋值语法

`a, b, ... = rhs1, rhs2, ...` — 两侧数量相等时是 `ParallelAssign` 节点，右侧全部先求值。  
`a, b = f()` — `f()` 返回元组时视为解构，等同于 `ParallelAssign`。  
两侧数量不等 → 编译错误。

## 后果

### 正面

1. **规则极简**：弃值规则只有一条，无例外路径；赋值限位通过句法强制，不依赖用户记忆类型规则。
2. **`never` 传播自然**：`ret`/`stop`/`skip` 类型为 `never`，dead code 检测直接从类型统一中得出。
3. **循环返回值统一**：`stop v` 模式让"find-first"等常见模式在类型系统中有清晰表达（`T?`）。
4. **工具链友好**：每个位置的类型可以静态确定，IDE 补全与类型推断不需要特殊 case。

### 负面

1. **弃值显式化增加噪音**：调用只要副作用的函数需要确保其返回 `void`，否则调用点必须写 `_ = ...`。
2. **尾随 `;` 禁止** 打破部分编辑器的自动补全习惯。
3. **`void` 字面量** 在极少数需要显式传递 `void` 值的场合略显奇特（`f(void)`）。

### 取舍权衡

选择"弃值必须显式 + 赋值限位 + `never` 底类型"的策略，优先保证：
- 代码意图可读（每一处弃值都是有意识的决定）
- 类型检查器实现简单（`never` 统一规则无特例）
- 自举编译器可靠性（句法错误比类型错误更早、更精确）

代价是调用者需要设计好函数的返回类型（尽量让副作用函数返回 `void`），以及尾随 `;` 的习惯需要调整。

## 实现检查清单

- [ ] 解析器在 `=` / `+=` 等出现在非语句顶层时报句法错误
- [ ] 块类型推断：取最后一个表达式类型；空块 → `void`
- [ ] 尾随 `;`（块内最后一个 token 是 `;`）报语法错误
- [ ] 非末尾非 `void` 表达式报弃值错误（`_ = expr` 豁免）
- [ ] `ret`/`stop`/`skip`/`jmp` 类型为 `never`，后续代码报 dead code 警告
- [ ] 条件链无 `_` 臂时，若臂类型非 `void`，报穷尽性错误
- [ ] 联合匹配 `? expr is` 在类型检查阶段验证穷尽性
- [ ] 循环 `stop v` 推断 `T?`；无限循环无 `stop` → `never`
- [ ] `unsafe { expr }` 类型透传
- [ ] `asm { }` 无标注默认 `void`，标注类型后透传
- [ ] 闭包类型从上下文推断；无上下文时要求显式标注
- [ ] `|>` 优先级低于算术/比较，左结合
- [ ] `::` 右侧求值使用与运行期相同的表达式规则
- [ ] `a, b = rhs1, rhs2` 两侧数量不等报编译错误
