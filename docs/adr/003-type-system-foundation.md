# ADR 003: 类型系统基础

## 状态

已接受（2026-08-01）

## 背景

Kore 的语法已固定（ADR 001、ADR 002），现在需要确定类型系统的基础设计：类型标注要求、推断边界、泛型机制、所有权语义、编译期求值范围等核心规则。这些决策直接影响编译器实现复杂度、类型安全保证、自举可行性。

关键问题：
1. 类型标注的强制程度（函数、结构体、字面量）
2. 类型推断的边界（局部 vs 全局、双向 vs 单向）
3. 数组、字符串、指针的类型表示与转换规则
4. 泛型的约束语法、推断策略、编译策略
5. trait 的方法、关联类型、动态派发机制
6. 所有权、可变性、错误处理在类型系统中的位置
7. 编译期求值的语法与能力边界

## 决策

### 原则

1. **显式优于推断** — 函数签名、结构体字段、联合变体必须显式标注类型；局部变量可推断。
2. **局部推断** — 类型推断限于函数内部，不跨越函数边界；采用双向推断（从上下文向下、从表达式向上）。
3. **零成本抽象** — 泛型默认单态化，动态派发需显式 `dyn Trait`；所有权移动无运行时开销。
4. **类型即文档** — 关键位置的类型标注是接口契约与自文档，不可省略。

### 类型标注与推断

#### 字面量类型（Q1）

整数字面量默认推断为 `i32`，浮点字面量默认 `f64`。双向推断从上下文调整：

```kore
x := 42              -- x: i32（默认）
y: i64 = 42          -- 42 推断为 i64
arr := [1u8, 2, 3]   -- 首元素确定，后续推断为 u8
```

#### 函数签名（Q3, Q8）

参数与返回值必须显式标注，`void` 不可省略：

```kore
add :: (a i32, b i32) i32 => a + b    -- 必须写返回类型
log :: (msg str) void => io.out.write(msg)  -- void 显式
```

闭包可省略类型（从上下文推断）：

```kore
items |> filter(\x => x > 0)  -- x 类型从 items 元素类型推断
```

#### 结构体与联合（Q5, Q6）

字段与变体载荷必须显式标注：

```kore
Vec3 :: {x, y, z f32}         -- 同类型合并，必须标注
Token :: .Num(i64) | .Sym(str) | .Nil  -- 变体载荷显式
```

#### 类型别名（Q7）

类型别名是透明的，与原类型完全等价：

```kore
UserId :: u64
uid: UserId = 123    -- UserId 与 u64 可互换
f :: (id u64) => ... 
f(uid)               -- 合法
```

需要名义类型时用单字段结构体包装：`UserId :: {val u64}`。

### 基础类型

#### 任意宽度整数（Q2）

`u1` 到 `u64`、`i1` 到 `i64` 是一等类型，用于硬件寄存器字段。运算规则：

- 同宽度运算：`u3 + u3 → u3`
- 不同宽度禁止：`u3 + u5` 是编译错误，必须显式 `as` 对齐
- 溢出语义：`+`（检查）、`+%`（环绕）、`+|`（饱和）

#### 数组与切片（Q10, Q11）

- `[N]T` — 固定长度数组，`N` 是类型一部分，编译期常量
- `[]T` — 动态切片，胖指针（指针 + 长度）

转换规则：
- 数组 → 切片：隐式（借用转换），`[3]i32` 可传给 `[]i32`
- 切片 → 数组：显式 `as [N]T`，返回 `[N]T?`（运行时长度检查）

#### 字符串（Q12）

`str` 是不可变 UTF-8 字节切片的语义类型，与 `[]u8` 不兼容：

```kore
s: str = "hello"
b := s.bytes()          -- 显式转换得 []u8
s2 := str.from_utf8(b)  -- 返回 str?（校验 UTF-8）
```

#### 指针（Q13, Q14）

- `^T` — 借用指针，不可为空，不拥有所指对象
- `^T?` — 可空借用指针，等价于 `(^T) | nil`
- `own ^T` — 所有指针，唯一所有，出作用域自动 drop

所有权移动：赋值与传参默认移动，原绑定失效。借用需显式 `^x`。

```kore
p1: own ^Node = alloc(Node{val: 1})
p2 := p1        -- 移动所有权，p1 不可再用
f(^p2)          -- 传借用，p2 仍有效
```

### 可变性（Q9）

可变性是绑定属性，不是类型的一部分。例外：指针的可变性是类型（`~^T` 可变指针）。

```kore
~x := 0         -- x 是可变绑定，类型是 i32
x = 1           -- 合法

f :: (y i32) => ...    -- y 在 f 内不可变
f :: (~y i32) => ...   -- y 在 f 内可变
```

### 泛型与 trait

#### 泛型约束（Q4, Q15）

类型参数用 `[T]`，约束写在类型参数声明处：

```kore
max :: [T: Ord](a, b T) T => ? a > b => a _ => b
sum :: [T: Add + Zero](items []T) T => ...
```

类型参数优先从实参推断，失败时要求显式：

```kore
max(3, 5)           -- 推断 [i32]
parse[i64](s)       -- 显式提供
```

#### trait 方法与关联类型（Q16, Q17）

trait 方法可以有默认实现，重写时无需关键字：

```kore
Iterator :: trait {
  Item :: type                        -- 关联类型
  next :: (~self ^Self) Item? => ...  -- 必需方法
  
  count :: (self ^Self) usz => {      -- 默认实现
    ~n := 0
    @ self.next() is v { n += 1 }
    n
  }
}

impl Iterator for Range {
  Item :: i32                         -- 指定关联类型
  next :: (~self ^Self) i32? => ...   -- 重写（无 override 关键字）
}
```

#### 动态派发与单态化（Q23, Q24）

泛型默认单态化（为每个类型实例生成特化代码）。需要动态派发时显式用 `dyn Trait`：

```kore
shapes: []^dyn Shape = [^Circle{r: 1.0}, ^Rect{w: 2.0, h: 3.0}]
@ shapes => s { s^.area() }  -- 通过 vtable 调用
```

`dyn Trait` 是胖指针（数据指针 + vtable指针），大小为两个指针。

### 类型转换与字面量

#### 结构体与联合字面量（Q20, Q21）

结构体字面量必须写类型名，支持字段简写：

```kore
p := Point{x: 1, y: 2}   -- 必须写 Point
Point{x, y}              -- x, y 同名时简写
```

联合变体构造支持上下文推断：

```kore
tok: Token = .Num(42)    -- 从 Token 推断 .Num
ret .Err(msg)            -- 从函数返回类型推断
Token.Num(42)            -- 显式写全也合法
```

#### `as` 类型转换（Q22）

所有类型转换必须显式。安全转换无需 `unsafe`，窄化/指针转换需要：

```kore
-- 安全转换（编译期或运行时检查）
x: i64 = y as i64        -- i32 → i64 拓宽
p: ^Base = q as ^Base    -- 子类型转换
s: []i32 = arr as []i32  -- [N]T → []T

-- 不安全转换（需要 unsafe 块）
unsafe {
  x: i32 = y as i32      -- i64 → i32 截断
  p: ^T = addr as ^T     -- usize → 指针
  q: ^U = p as ^U        -- 无关类型指针转换
}
```

### 错误处理（Q18, Q19）

#### 错误传播 `!`

`!` 是后缀运算符，优先级高于方法调用：

```kore
f()!.method()            -- 解析为 (f()!).method()
x.field!.method()        -- 解析为 (x.field)!.method()
```

等价于：`? f() is { .Ok(v) => v _ => ret it }`

#### 可选链 `?`

`?` 用于可选类型展开，nil 时提前返回 nil：

```kore
obj?.field?.method()?    -- 任一步为 nil 则返回 nil
```

等价于：`? obj is { v => v.field ... nil => ret nil }`

### 编译期求值（Q25）

`::` 右侧的表达式在编译期求值，支持任意运行期语法（函数调用、分支、循环）：

```kore
SIZE :: compute_size()   -- 函数调用

TABLE :: {               -- 块、循环
  ~t := [256]u8{..0}
  @ 0..256 => i { t[i] = crc(i as u8) }
  t
}

Config :: ? MODE is {    -- 分支
  .Dev  => DevConfig{...}
  .Prod => ProdConfig{...}
}
```

限制：不能调用 I/O、不能访问运行期变量。编译器内置求值器执行相同语义的代码。

## 后果

### 正面

1. **类型安全与可预测性** — 显式标注在函数/结构体边界保证接口清晰；局部推断减少冗余但不牺牲可读性。
2. **编译器实现简单** — 无需全局类型推断、流敏感分析；双向推断算法成熟（Hindley-Milner）。
3. **零成本抽象** — 单态化泛型、移动语义、显式转换全部编译期完成，无运行时开销。
4. **强大的编译期能力** — `::` 右侧可执行任意代码，支持静态查表、代码生成，代替宏系统。
5. **自文档代码** — 类型标注、关联类型、约束全部显式，阅读代码无需追溯上下文。

### 负面

1. **函数签名冗长** — 必须写参数与返回类型，即使从体可推断；`void` 必须显式。
2. **数值转换繁琐** — 任意宽度整数不同宽度禁止运算，需频繁 `as` 对齐。
3. **字符串与字节切片分离** — `str` 与 `[]u8` 不兼容，转换需显式调用方法。
4. **泛型单态化膨胀** — 每个类型实例生成一份代码，编译时间与二进制大小增长。

### 取舍权衡

选择"显式标注 + 局部推断 + 单态化泛型"的策略，优先保证：
- 类型系统可预测（编译期确定所有类型，无隐式规则）
- 自举编译器可行（推断算法简单，无需复杂的全局分析）
- 运行时性能（零成本抽象，单态化代码可内联优化）

代价是显式标注增加书写量、单态化增加编译时间。这些代价在系统编程领域可接受（可预测性与性能优先于便利性）。

## 实现检查清单

- [ ] 整数/浮点字面量默认类型推断（i32/f64）
- [ ] 双向类型推断算法（局部，不跨函数）
- [ ] 函数签名检查：参数、返回值、`void` 必须显式
- [ ] 结构体字段、联合变体载荷类型检查
- [ ] 类型别名透明展开
- [ ] 任意宽度整数（u1-u64, i1-i64）类型定义与运算检查
- [ ] 数组 `[N]T` 与切片 `[]T` 类型；数组→切片隐式转换
- [ ] `str` 类型与 `[]u8` 的分离；`bytes()` / `from_utf8()` 方法
- [ ] 借用指针 `^T` 非空检查；可空指针 `^T?`
- [ ] 所有指针 `own ^T` 移动语义与生命周期检查
- [ ] 可变性检查：绑定层面（`~x`）与指针类型层面（`~^T`）
- [ ] 泛型约束语法解析 `[T: Trait1 + Trait2]`
- [ ] 泛型类型参数从实参推断
- [ ] trait 方法默认实现与重写检查
- [ ] 关联类型 `Type :: type` 语法与实现绑定
- [ ] 结构体字面量类型名检查；字段简写 `{x, y}` 展开
- [ ] 联合变体构造上下文推断 `.Num(42)`
- [ ] `as` 转换安全性检查：拓宽合法，窄化/指针转换需 `unsafe`
- [ ] `dyn Trait` 胖指针表示；vtable 生成
- [ ] 泛型单态化：为每个类型实例生成特化代码
- [ ] 错误传播 `!` 与可选链 `?` 优先级与展开
- [ ] 编译期求值器：执行 `::` 右侧表达式，限制 I/O 与运行期变量
