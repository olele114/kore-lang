# ADR 004: 作用域与绑定规则

## 状态

已接受（2026-08-01）

## 背景

Kore 有两套绑定记号（`::` 编译期、`:`/`:=` 运行期）、多种引入名字的构造（参数、模式、循环、泛型参数、模块导入、嵌入）以及若干特殊块（`unsafe`、`asm`、`impl`）。ADR 001/002/003 定下了 AST 分类、表达式边界与类型系统，但没有回答"一个名字在哪里可见、哪个名字优先、什么时候可以重名"。

本 ADR 固定名字的引入、可见性、遮蔽、查找顺序，使解析器、类型检查器与 IDE 的名字解析行为一致。

关键问题：
1. 遮蔽在什么情况下允许？同作用域重复绑定是否合法？
2. 编译期绑定与运行期绑定是否共享名字空间？类型名与值名是否共享？
3. 编译期绑定能否依赖运行期值？
4. 闭包捕获、循环绑定、模式绑定各自的作用域与生存期？
5. 模块导入、可见性、跨模块访问的规则？
6. 裸名字的查找链是什么？

## 决策

### 原则

1. **单一名字空间** — 类型、函数、常量、变量、模块别名共用一套名字，一个作用域内一个名字只指一个东西。解析器不需要"此处期望类型还是值"来消歧。
2. **一条查找链** — 由内向外逐层，不按绑定种类分叉。
3. **块即作用域** — 除 `asm` 输出操作数外，所有引入作用域的构造都是块，行为一致。
4. **编译期不依赖运行期** — `::` 的右侧只能看到编译期已知的名字。
5. **来源可见** — 跨模块名字必须限定，不做隐式名字注入。

### 遮蔽与重绑定

| 情形 | 规则 |
|------|------|
| 同作用域重复 `:=` 同名 | **编译错误**（几乎总是笔误，本意是 `x = 2`） |
| 内层作用域遮蔽外层同名 | **允许** |
| 局部 `:=` 遮蔽顶层 `::`（常量/函数/类型名） | **允许**，被遮蔽者仍可经模块限定访问（`mod.MAX`） |
| 同作用域内 `::` 与 `:=` 同名 | **编译错误**（共享名字空间，属同层重绑定） |
| 函数体遮蔽参数名 | **允许**（参数在外层，函数体是内层） |
| 局部绑定遮蔽内置名字（`i32 := 5`） | **允许**（内置名字在查找链末端），linter 警告 |
| 遮蔽 `Self` / `self` | **禁止**（`impl` 上下文内置名字，不可遮蔽） |

不允许同作用域重复绑定的理由还有一条：否则用户可以用重复绑定绕过 `~` 可变性标记，`~` 的防护失效。

### 名字空间

单一名字空间，包含：类型名、函数名、常量名、变量名、模块别名、泛型参数名。

不参与普通名字解析的形式：

| 形式 | 说明 |
|------|------|
| `.Variant` | 前导点表示"从期望类型中查找变体"，独立语法形式，变体名不污染名字空间 |
| `Self` / `self` | `impl` 上下文内置，不可遮蔽 |
| 字段名 / 方法名 | 属于类型的成员空间，只经 `.` 访问 |

联合变体两种写法都合法：`Shape.Circle(1.0)`（完整限定）与 `.Circle(1.0)`（从上下文推断，依赖 ADR 003 的双向推断）。

### 编译期与运行期的边界

块内 `::` 的右侧只能引用：顶层 `::` 绑定、同块 `::` 绑定、字面量、编译期参数。

```kore
f :: (n i32) void => {
  m := n * 2
  SIZE :: m + 1        -- 编译错误：编译期绑定不能依赖运行期值
}
```

错误在绑定处报出而非使用处。不做"常量传播后再判定"——那会让合法性依赖优化级别。

嵌套函数（`::`）遵循同一规则：可访问外层 `::` 绑定与参数（签名编译期已知），**不能**访问外层 `:=` 绑定。闭包（`\`）是运行期构造，可捕获全部外层名字。

### 闭包捕获

- 隐式捕获：只读用借用 `^T`，被写用可变借用 `~^T`
- 闭包是栈值，受不逃逸检查约束（与借用指针同一条规则）
- 需要逃逸时用户显式把数据复制进结构体或用 `own`

不引入显式捕获列表：管道场景 `\x => x > threshold` 若要写成 `\[threshold] x => ...` 噪音过大。

### 循环绑定

| 形式 | `x` 的类型 | 语义 |
|------|-----------|------|
| `@ items => x` | `T` | 值副本，不可变 |
| `@ items => ~x` | `~T` | 可变副本，修改不影响源容器 |
| `@ ~items => x` | `~^T` | 可变借用，`x^ = 0` 原地写源容器 |

每轮迭代是逻辑上的新绑定。`^x` 的借用不能逃逸出本轮迭代（由不逃逸检查覆盖）。

`stop` / `skip` **只作用于最内层循环**，不提供标签机制，也不提供数字层级。多层跳出用 `ret`（通常意味着该抽取成函数）。理由：标签会引入一整套新名字空间（标签名的作用域、遮蔽规则、与变量名的关系），成本高于收益。

### 模式绑定

作用域严格限于该臂的体：

```kore
? tok is {
  .Num(n) => use(n)      -- n 只在本臂可见
  .Sym(s) => use(n)      -- 错误：n 不在此臂
}

? tok is .Num(n) => ret n    -- 守卫形态，n 只在守卫体内
after()                      -- n 在此处不可见
```

守卫形态不泄漏绑定。理由：读代码时不必回溯守卫；守卫的典型用法是早退，泄漏无实际价值；泄漏需要控制流分析确认守卫体必然发散，规则会变复杂。

### 泛型参数

作用域覆盖其声明所在的整个构造（签名 + 体）。`impl` 块是独立构造，必须重新声明泛型参数，参数名可与类型定义处不同：

```kore
Pair :: [A, B] { first A, second B }
Pair :: [A, B] impl {
  swap(^self) Pair[B, A] => Pair[B, A]{self.second, self.first}
}
```

不做跨构造的隐式泛型参数继承。

### 模块与可见性

**导入**：`use` 只能出现在文件顶层或模块声明内，作用域是整个模块。函数内 `use` 非法——否则同一模块的不同函数看到不同名字空间，工具链难以处理。

**引用形式**：只支持限定引用 `模块名.名字`。不支持选择性导入（`use std.io.{print}`），不支持通配导入（`use std.io.*`）。每个名字的来源在使用点可见。

**别名**：复用 `::` 记号。

```kore
hm :: use std.collections.hashmap
ds :: use mylib.internal.data.structures
```

裸 `use std.io` 是 `io :: use std.io` 的省略形式（默认取路径最后一段作名字）。不引入 `use ... as ...`——`as` 在 Kore 已用于类型转换。

**可见性**：两级——默认模块私有，`pub` 对所有导入者可见。不提供 `pub(crate)` / `pub(path)` 等中间层级。包内边界由目录约定和文档表达，不由类型系统强制。

**字段可见性以模块（文件）为边界**：同模块内所有代码可访问彼此的私有字段。

```kore
pub File :: { pub path str, fd i32 }
Logger :: { f File }
Logger :: impl {
  dump(^self) i32 => self.f.fd    -- 合法：同模块
}
```

模块是唯一的封装单元，不引入"类型私有"这第二种边界。

### `impl` 块

同一类型的所有 `impl` 块在模块内互相可见，方法名字解析在整个类型的方法集合中进行。`impl` 块只是组织方式（按功能分组），编译器合并为统一方法表，块间顺序无关。

### 特殊块

| 构造 | 作用域行为 |
|------|-----------|
| `unsafe { }` | 普通块，引入新作用域；内部绑定不泄漏到外层 |
| `asm { }` | **不引入作用域**；输出操作数绑定到 `asm` 所在的外层作用域 |
| 块内 `::` | 作用域限于该块，顺序无关（两遍扫描） |

`asm` 的输出必须能被后续代码使用，所以操作数绑定在外层。这是唯一的例外。

### 名字解析顺序

给定裸名字 `foo`：

```
1. 局部作用域（由内向外逐层）
2. 模块顶层 :: 绑定
3. 内置名字（true / false / nil / void / i32 / usz / str / ...）
```

找不到即报错，**不隐式搜索导入的模块**（与"只支持限定引用"一致）。

内置名字在末端意味着可被遮蔽。不引入"保留名字"列表这一额外规则。

### 模块内 `::` 的解析

两遍扫描：

1. 第一遍收集所有 `::` 名字及其位置（不解析体）
2. 第二遍解析体内引用

允许任意前向引用。循环引用在第二遍检测：

- 循环类型别名 `A :: B; B :: A` → 展开时报错
- 递归类型经指针中断 `Node :: { val i32, next ^Node? }` → 合法（指针大小已知，无需展开）
- 相互递归函数 → 合法（签名在第一遍已知）

### 未使用绑定

| 情形 | 处理 |
|------|------|
| 未使用的 `:=` 局部绑定 | 警告 |
| 未使用的参数 | 警告 |
| `_` 前缀名（`_z`、`_unused`） | 豁免警告 |
| 未使用的 `::` 绑定 | 不警告（可能是导出的 API） |

警告而非错误：错误会打断调试期的探索性编码（注释掉一行导致编译失败）。`_` 前缀提供显式的"我知道它没用"表达。

## 后果

### 正面

1. **解析器无需类型信息** — 单一名字空间 + 前导点变体形式，让名字解析完全独立于类型检查，支持一遍语法分析。
2. **查找链短且确定** — 三层，无按绑定种类的分叉，IDE 的"跳转到定义"实现简单。
3. **编译期边界清晰** — `::` 不能引用运行期值这一条硬规则，让"编译期"概念不会被侵蚀，错误位置精确。
4. **不逃逸检查复用** — 闭包捕获、循环绑定借用、模式绑定都归到同一条借用生存期规则下，不引入生命周期标注。
5. **可见性规则极简** — 一个 `pub` 标记、一个模块边界，覆盖字段与方法与类型。

### 负面

1. **无标签跳转** — 嵌套循环多层跳出必须重构成函数或用布尔标志，某些解析器/状态机代码会显得绕。
2. **必须限定引用** — 高频使用的模块名会反复出现（`io.out.print`），别名机制缓解但不消除。
3. **类型名可被遮蔽** — `Counter := 5` 后该作用域内 `Counter` 不再是类型，需靠 linter 提示而非编译器。
4. **无包内可见性** — `pub` 的内部实现细节会暴露给外部使用者，只能靠目录命名约定（`internal/`）表达意图。
5. **嵌套函数受限** — `::` 嵌套函数不能访问外层 `:=`，某些场景必须改用闭包或显式传参。

### 取舍权衡

核心取舍是**用"规则少"换"表达力"**：

- 放弃标签、放弃细粒度可见性、放弃选择性导入——每一项都会引入新名字空间或新层级
- 换来的是名字解析可以用三层查找链 + 两遍扫描完整实现，这对自举编译器（Kore0 要能被一个小编译器接受）是关键约束

单一名字空间是最有争议的决定。代价是类型名可被局部变量遮蔽；收益是解析器不需要在语法分析阶段就知道类型信息，这直接支撑了设计原则 4（语法易于机器解析）。

## 实现检查清单

- [ ] 同作用域重复 `:=` 同名报错，提示"是否想写 `x = ...`"
- [ ] 内层遮蔽外层合法；遮蔽顶层 `::` 时被遮蔽者仍可经模块限定访问
- [ ] 同作用域 `::` 与 `:=` 同名报错（共享名字空间）
- [ ] 函数体作为参数的内层作用域，允许遮蔽参数名
- [ ] `Self` / `self` 标记为不可遮蔽，遮蔽尝试报错
- [ ] 块内 `::` 右侧引用运行期绑定时，在绑定处报"编译期绑定不能依赖运行期值"
- [ ] 嵌套 `::` 函数体内引用外层 `:=` 报同类错误
- [ ] 闭包捕获分析：只读 → `^T`，被写 → `~^T`；捕获集接入不逃逸检查
- [ ] 循环绑定三形态的类型推断：`x: T` / `~x: ~T` / `@ ~items => x: ~^T`
- [ ] 循环绑定每轮新鲜；`^x` 借用不得逃逸本轮迭代
- [ ] `stop` / `skip` 绑定到最内层循环；无标签语法
- [ ] 模式绑定作用域限于臂体；守卫形态不泄漏到后续代码
- [ ] `.Variant` 作为独立语法节点，不进入普通名字查找
- [ ] 泛型参数作用域覆盖声明所在构造；`impl` 独立声明，不继承类型定义处的参数名
- [ ] `use` 出现在非顶层位置报语法错误
- [ ] 拒绝 `use m.{a, b}` 与 `use m.*` 形式
- [ ] `别名 :: use 路径` 支持；裸 `use a.b.c` 等价于 `c :: use a.b.c`
- [ ] 可见性检查：非 `pub` 名字跨模块访问报错；同模块内字段访问无限制
- [ ] 同类型多个 `impl` 块合并为统一方法表，块间顺序无关
- [ ] `unsafe { }` 引入作用域；`asm { }` 输出操作数绑定到外层
- [ ] 名字解析三层查找链：局部（内→外）→ 模块顶层 `::` → 内置；不搜索导入模块
- [ ] 模块内 `::` 两遍扫描；循环类型别名报错；经指针的递归类型合法
- [ ] 未使用的 `:=` 与参数报警告；`_` 前缀豁免；未使用 `::` 不警告
