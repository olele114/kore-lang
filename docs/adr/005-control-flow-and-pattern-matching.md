# ADR 005 — 控制流与模式匹配

**状态**: 已决定  
**日期**: 2026-08-02  
**关联**: ADR 001（语法糖边界）、ADR 002（表达式边界）、ADR 003（类型系统）、ADR 004（作用域与绑定）

---

## 背景

本 ADR 通过 25 轮拷问固定 Kore 语言的控制流与模式匹配设计。核心目标：

1. `?` 与 `@` 的三种形态在语义上统一，不引入特例
2. 模式匹配提供编译期安全保证（穷尽性、可达性），但算法复杂度可控
3. 所有决定与 ADR 001-004 的已有选择保持一致

---

## 决定

### D1 — 循环标签：不提供

删除 `docs/spec/02-syntax.md` 中的 `@ :outer` 标签语法（与 ADR 004 D24 一致）。多层跳出通过 `ret` 实现（将循环体抽为函数）。

**理由**: 标签引入独立名字空间（作用域、遮蔽、与变量名冲突），自举编译器实现成本高于收益。

---

### D2 — 八种模式，全部为核心 AST 节点

```
字面量       42, true, "hi"
变体         .Num(n)
切片         [h, ..t], [], [x]
元组         (a, b)
结构体       Point{x, y, ..}
范围         1..=9
裸绑定       n
通配         _
```

所有形式保留为 AST 节点，不脱糖（ADR 001 边界：只有 `T?` 脱糖）。

---

### D3 — 模式守卫：`and` 关键字

```kore
? x is {
  .Num(n) and n > 0 => ...
  .Num(n) and n < 0 => ...
  .Num(_) => ...     -- 守卫未覆盖的情况需显式兜底
}
```

`and` 复用已有关键字，语义为"匹配该模式且满足条件"。`?` 在此位置会与外层 `? expr is` 混淆，故不用。

---

### D4 — 或模式：`|` 连接

```kore
.Plus | .Minus => "additive"
0 | 1 => "small"
```

各分支须绑定完全相同的名字集合，否则编译错误。`|` 复用联合类型声明的符号，语义对称。

---

### D5 — 守卫臂的穷尽性：要求显式兜底

有守卫的臂视为"不完全覆盖"。即使所有联合变体都出现了，只要有任意臂带守卫，编译器要求额外的无守卫兜底臂（`_` 或具体的无守卫模式）。

**理由**: 守卫条件是任意布尔表达式，编译器无法静态证明互补性。不引入 SMT 求解，保守要求兜底比静默 panic 安全。

---

### D6 — 匹配顺序：自上而下，完全不可达臂报警告

- 第一个匹配的臂胜出（顺序语义）
- 完全被前面臂覆盖的臂（不可达）：**警告**
- 部分重叠（如 `1..=10` 与 `5..=15`）：合法，无警告

---

### D7 — 切片模式：最多一个 `..`，支持六种位置

```kore
[]             -- 空
[x]            -- 精确一个
[h, ..t]       -- 前缀 + 尾绑定
[..init, l]    -- 前缀绑定 + 尾
[a, .., b]     -- 首尾 + 中间忽略
[a, b, ..]     -- 前 N 个 + 其余忽略
```

每个切片模式最多一个 `..`（可带绑定或不带）。实现用常数次长度检查 + 偏移计算，无回溯。

---

### D8 — 切片穷尽性：长度区间分析

- `[]T`（动态切片）：通过长度区间并集判定穷尽（`0`、`1`、`≥1` 覆盖全部）
- `[N]T`（固定数组）：长度静态已知，`[x, y, z]` 匹配 `[3]T` 即穷尽，无需 `_`

---

### D9 — 不可失败模式用于绑定位置

```kore
(a, b) := get_pair()        -- 合法（元组解构，不可失败）
Vec3{x, y, z} := get_vec()  -- 合法（结构体解构，不可失败）
[p, q] := get_arr3()        -- 合法（固定数组解构，不可失败）
.Num(n) := tok              -- 编译错误（可失败模式）
```

参数位置**不允许**解构（函数签名同时是文档与 ABI 描述）。

---

### D10 — 模式绑定的可变性与借用

- 默认按值绑定（Copy 类型拷贝，non-Copy 类型移动或借用取决于被匹配值）
- `~x`：可变的局部绑定
- `^x` / `~^x`：显式借用绑定

与 `~`/`^` 的全局含义完全一致，不引入模式专用修饰符。

---

### D11 — `Range[T]` 是统一的一等类型

`a..b` / `a..=b` 类型为 `Range[T]` / `RangeInclusive[T]`。

- 在 `@` 后：要求实现 `Iter` trait
- 在 `? is` 臂里：做边界比较
- 作为值存储：合法（`r := 0..=9`，类型 `RangeInclusive[i32]`）

---

### D12 — `stop` 不带值等价于 `stop void`

同一循环内所有 `stop` 必须携带相同类型的值。混用 `stop`（void）与 `stop v`（具体类型）是类型错误。

---

### D13 — `Iter` trait 协议

```kore
Iter :: trait [Item] {
  next(~^self) Item?
}
```

单一必需方法。`map`/`filter`/`zip` 等组合子作为 trait 默认方法提供。可失败迭代用 `Item? ! Err`（即 `Result[Item?, Err]`）表达。

---

### D14 — `skip` 统一语义：进入下一轮

| 循环形态 | `skip` 的机制 |
|---------|-------------|
| 条件循环 `@ cond {}` | 跳到循环头重新检查条件 |
| 范围循环 `@ 0..n => i {}` | 自增索引，跳到下一轮 |
| 迭代循环 `@ items => x {}` | 调用 `iter.next()`，跳到下一轮 |

---

### D15 — 循环变量默认不可变，`~` 标记可变

```kore
@ 0..n => i { i = i + 1 }      -- 编译错误
@ 0..n => ~i { i = i + 1 }     -- 合法，修改不影响下一轮初始值
@ items => ~x { x.field = 0 }  -- 合法，修改的是当前轮的拷贝
```

ADR 004 D5 已定"循环绑定每轮新鲜"，可变修改只影响当前轮局部副本。

---

### D16 — 匹配表达式双向类型推断，无隐式转换

所有臂类型必须统一为同一个 `T`（可由上下文约束推断）。臂之间类型不一致报错，不做隐式提升（与 ADR 003 D2 一致）。

---

### D17 — 守卫臂体：单表达式或显式块

```kore
? x < 0 => ret .Err(.Neg)    -- 合法：单表达式
? x < 0 => { log(); ret e }  -- 合法：显式块
? x < 0 => log() ; ret e     -- 非法：; 在臂位置是臂分隔符
```

---

### D18 — 条件链短路求值

`? { cond1 => ... ; cond2 => ... }` 自上而下，第一个为真的臂胜出，后续条件不再求值。

---

### D19 — 被匹配表达式求值恰好一次

`? expr is { }` 中 `expr` 求值一次，结果缓存到临时变量供所有臂匹配使用。

---

### D20 — 不限制模式嵌套深度

语法层面无限制。实现通过递归下降处理，栈深度超过实现阈值（如 1000 层）时报错——这是实现限制而非语法规则。

---

### D21 — 决策树编译，贪心标签优先

编译器将模式匹配编译为决策树：优先检查联合判别字段（tag），再按臂声明顺序细分字段和嵌套匹配。

不做回溯，不做概率分析。后端优化器可将稠密变体转为跳转表——这是代码生成优化而非语义决策。

---

### D22 — 穷尽性分析：有限组合完整分析，无限域保守处理

- 联合变体 × 结构体字段 × 有限切片长度：执行完整覆盖分析（矩阵算法）
- 整数范围、字符串等无限域的笛卡尔积组合：保守要求显式 `_` 兜底

---

### D23 — 不可达臂检测：完全覆盖报警告

检测完全被前面臂覆盖的臂（包括范围覆盖 `0..=100` 覆盖 `50`）。算法是穷尽性检查的逆向应用。

部分重叠合法（D6），不报警告。

---

### D24 — 结构体模式：字段任意顺序，省略需 `..`

```kore
Point{y, x, ..} => ...    -- 合法：任意字段顺序
Point{x, ..} => ...       -- 合法：显式忽略其余字段
Point{x, y} => ...        -- 编译错误：省略字段未声明
```

`..` 强制显式化忽略，防止结构体新增字段后旧代码静默失配。

---

### D25 — 三种循环形态统一返回 `T?`

```kore
x := @ cond { ... stop 42 }         -- x : i32?
y := @ 0..n => i { ... stop i }     -- y : i32?
z := @ items => it { ... stop it }  -- z : T?
```

未执行 `stop` 时循环值为 `nil`（`T? = nil`）。`T` 从 `stop` 的值推断。三种形态行为完全统一（ADR 002 已定基础规则）。

## 被拒绝的设计

| 设计 | 拒绝原因 |
|------|---------|
| 循环标签 `@ :outer` | 引入独立名字空间，自举成本高（D1） |
| 模式专用 `ref`/`ref mut` | 与已有 `^`/`~` 重复表达（D10） |
| 整数域完整笛卡尔积穷尽性分析 | 病态输入编译时间爆炸（D22） |
| 条件链全量求值 | 副作用不可控，无任何优势（D18） |
| 参数位置解构 | 破坏函数签名可读性与 ABI 文档性（D9） |
| `stop`/`skip` 的数字层级 | 重构时数字与结构耦合，易错（ADR 004） |
