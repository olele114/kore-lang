# ADR 010: 编译器测试策略与基准

## 状态

已接受（2026-08-04）

## 背景

前九个 ADR 定了语言语义与编译器结构，但没有定**如何验证实现是对的**。这不是补充细节，而是自举项目的前置条件：stage1 之后，编译器的唯一裁判是它自己，任何未被测试固定住的行为都会在下一次自编译中静默漂移。

本 ADR 通过 14 个问题确定测试的书写形式、自举与目标验证、性能判据、主动找错手段、分层预算、覆盖判据与增长规则。

三个约束贯穿全程，先在此列明，后续多处决策直接引用：

1. **测试基础设施不能依赖被测对象。** 用语言内测试框架测这门语言的编译器，等于让待验证的功能承载验证过程。
2. **开发机是 Android/Termux 移动 aarch64。** 热降频导致墙钟时间方差超过 20%；`perf_event_open` 大概率被禁；valgrind 与 sanitizer 不可靠。x86_64 是交叉目标而非宿主。
3. **本目录当前不是 git 仓库，也没有 CI。** 因此任何判据都不能表述为 CI 配置，必须表述为**预算与树内声明**，以便版本控制与 CI 后来引入时判据不变。

## 决策

### 原则

1. **确定性代替统计** — 能变成字节相等或计数相等的判据，一律不用阈值与百分比。这条在本轮反复胜出（不动点、性能回归、内存毒化三处独立收敛到它）。
2. **不可满足或高噪的门比没有门更坏** — 它会被绕过、被忽略，并在被忽略期间提供假信心。
3. **摩擦不能落在希望被高频执行的动作上** — 判据的成本必须与它捕获的问题成比例。
4. **缺口要有确定答案，但不必自动阻断** — 覆盖以清单呈现，阈值门会诱发为凑指标而写的空断言。

### 1. 测试的书写形式（Q1–Q3）

#### 文件驱动 runner（Q1）

测试由**外部 runner** 驱动：runner 遍历两个根——`tests/` 下的 `.kore` 文件，以及编译器树内与实现同目录的 `*_test.kore` 文件——对每个文件调用编译器，检查产物与退出码。**不引入语言内测试框架**（无测试属性、无注册宏、无反射发现）。

理由是约束 1：测试框架若用 Kore 写成，它依赖 trait、泛型、编译期求值——而这些正是最需要被测试的部分。框架一旦有 bug，失败会表现为"所有测试都错"或更糟的"所有测试都过"。

ADR 007 Q21 定的 `*_test.kore` 单元测试不与本条冲突：那些文件是**普通 Kore 程序**，`main` 里做自检，由同一个 runner 调用，不是框架的宿主。它们按 ADR 007 与实现同目录（如 `frontend/lexer/token_test.kore`）而不在 `tests/` 下，所以层归属按规则确定而非按声明确定，见 Q12。

#### 行内注解为主，结构化转储为辅（Q2）

诊断测试的期望**写在源文件里**，紧贴触发它的那一行：

```kore
x := "hello" + 1    --~ E4001 类型不匹配
```

`--~` 是测试注解记号（在编译器眼里是普通注释）。runner 提取注解，与编译器实际产出的诊断做**双向**匹配：注解有而诊断无 = 失败；诊断有而注解无 = 失败。单向匹配放过的正是最危险的一类——编译器多报了一条错，用例照旧绿。

**不用 `.expected` 快照文件**作为主形式。快照与源文件的耦合点是行号：源文件插一行，整个 `.expected` 失效，而修复动作是重新生成快照——一个"看一眼、按一下"的动作，长期必然退化为不看就重新生成。行内注解没有行号耦合，因为它就在那一行上。

行内注解只能表达「这一行有这个码」。诊断的**结构**——子诊断的层级、note 挂在哪个 span、span 的精确范围——没有落在单一行上，注解表达不了。这少数用例走 ADR 009 Q7 已定的 `--error-format=json`（带 `"version": 1` 作为演化锚点），由 runner 解析后比对字段。

**不为测试新增 `--emit` 阶段。** ADR 009 的八个阶段（`tokens`、`ast`、`resolved`、`typed`、`ir`、`llvm-ir`、`asm`、`obj`）是 pipeline 的中间产物，诊断不是其中一环——它是横切所有 pass 的输出，已经有自己的通道。为测试加第九个阶段是把测试需求塞进一个语义不符的接口。

JSON 通道用于结构比对有两个已经就位的前提：ADR 009 Q14 定了诊断在编译结束时按 `(file, lo)` 统一排序（顺序稳定，否则并行编译下无法比对），Q7 定了三个 renderer 消费同一份 `[Diagnostic]`（JSON 与 human 不会分叉）。

#### 机器级契约用注解断言（Q3）

「生成的代码有没有做对的事」这类断言，不比对汇编文本，而是声明**契约**，由编译器在对应 pass 里自检：

```kore
count :: (n i32, acc i32) i32 => ? n == 0 => acc : jmp count(n - 1, acc + n)
--= tailcall count

reg := (vol ^u32)(0x4000_0000)
_ = reg^        --= volatile-load u32
```

`--=` 断言在编译器内部有检查点（`jmp` 是否真的降为跳转而非调用、`vol` 访问是否真的没被合并或消除）。这些是**语义保证**而非优化——CONTEXT.md 明确 `jmp` 叫「保证尾调用」不叫 TCO——所以它们必须有测试，且测试不能因后端改进而失效。

**记号选 `--=` 而非 `--!`。** ADR 008 第 5 节已把 `--!` 定为模块级文档注释，且限定只能出现在文件顶部——而契约断言要出现的位置恰好是行尾。同一记号两个含义违反 spec 01「每个记号只有一个含义」，位置规则还正面冲突。`--=` 未被占用：`--` 是行注释，`---` 是项文档，`--!` 是模块文档，`--~` 是测试注解，`--=` 是契约断言，词法上都靠 `--` 之后的第三个字符区分。`=` 取「等于承诺」之意。

**不用汇编快照。** 汇编快照把摩擦精确地放在最该鼓励的动作上：改进寄存器分配、改进指令选择，都会让一大批快照变红，而它们全是假阳性。这违背原则 3。

**用例自检、退出码单通道上报。** 运行时行为的验证由用例自己的 `main` 完成，通过退出码报告结果，不打印、不比对 stdout。退出码是唯一不依赖任何库的通道——而 `tests/` 里的用例可能是 `core` 层的、不能假设有格式化输出。

> 例外见 Q5：`bare/` 目标没有进程也没有 `exit`，这条前提在那里不成立。

### 2. 自举与目标验证（Q4–Q5）

#### 自举不动点是 stage2 == stage3（Q4）

```
记 K = 用 Kore0 写成的编译器源码，S = 用完整 Kore 写成的编译器源码

stage0（Rust）──编译 K（Kore0 子集）──> stage1
stage1          ──编译 S──────────────> stage2
stage2          ──编译 S──────────────> stage3

判据：stage2 == stage3（逐字节）
```

**这修订了 ADR 007 Q22 图中的「stage2 — 验证：stage1 编译自己，输出与 stage1 一致」。** 那条不动点不可满足：stage1 的二进制由 stage0 经 LLVM 后端产出，stage2 的二进制由 stage1 经自举后端产出，两个不同的编译器编译同一份源码，没有任何理由产出相同字节。

正确的不动点在下一跳：stage1 与 stage2 是**行为等价的两个编译器**（stage1 由 Kore0 重写版 `K` 构建，stage2 由完整源码 `S` 构建；若 `K` 与 `S` 描述同一套编译行为，则两者作为编译器等价），因此它们编译同一份 `S` 必须得到相同字节。不动点在 stage2 与 stage3 之间，而不在 stage1 与 stage2 之间——后者连源码都不同。这与 CONTEXT.md 已写的「自举闭合的判据是 stage2 与 stage3 的产物逐字节相同」一致——ADR 007 的图是与词汇表不同步的那一方。

保留旧判据的代价是自举永远无法宣布完成。**不可满足的验收条件比错误的测试更坏**：错误的测试会失败并被修，不可满足的条件只会被无限期搁置，最终被静默删除。

#### `bare/` 提供 `test_exit` 内置（Q5）

freestanding 目标没有进程、没有 `exit`、没有 stdout。Q3 的「退出码单通道」在那里无处落地。

`bare/` 因此提供一个内置 `test_exit(code)`，在 QEMU 下降为平台特定的关机序列（x86_64 用 ISA debug-exit 端口，aarch64 用 semihosting 或 PSCI）。**这是唯一的目标特定测试设施**——把特殊性压缩到一个函数，其余测试代码在 hosted 与 bare 之间完全一致。

按 ADR 007，`bare/` 是 `x86_64` 与 `aarch64` 共享的裸机抽象而非第三个架构，所以 `test_exit` 属于 `bare/` 而非各架构目录。

### 3. 双实现一致性（Q6）

编译期求值器（ADR 007 `frontend/eval/`）是 Kore 的**第二个实现**。ADR 002 已定「`::` 右侧遵循与运行期完全相同的表达式规则，区别仅是求值时机」——这句话是一个可测的断言：同一个表达式走 eval 路径与走 codegen 路径，结果必须一致。

这构成独立测试族：同一份表达式，一路在 `::` 里求值、一路在运行期函数里求值，比对结果。

```kore
expected :: fib(20)              -- eval 路径
main :: () void => {
  actual := fib(20)              -- codegen 路径
  ? actual != expected => test_exit(1)
  test_exit(0)
}
```

这一族必须存在，因为两个实现的分歧不会在任何单侧测试中暴露。而分歧概率很高：Kore 允许任意函数在 comptime 运行（不限于纯函数），意味着整数溢出语义、位运算边界、浮点舍入、`T?` 与 `T ! E` 的传播都要在两处独立实现。

递归深度是这一族里的特例，需要单独说明：eval 的深度／步数上限尚无 ADR 定义（ADR 009 Q20 只把编译期求值步数计数器定为「将来加上限的现成基础设施」）。一旦定了上限，它与 codegen 的栈行为就是两套机制，一致性无法要求——**深度上限处的行为差异不在本族的比对范围内**，这一族只比对两侧都能完成求值时的结果。

**不做随机表达式生成来喂这一族。** 随机生成要先有「良构表达式」的模型，而这个模型本身就是类型检查器的一份重述——写它等于写第三个实现。见 Q9。

### 4. 性能判据（Q7–Q8）

#### 回归判据是确定性计数器的精确相等（Q7）

性能回归**不用墙钟百分比阈值**。约束 2 使这条路不通：移动设备热降频让方差超过 20%，于是 5% 阈值天天误报，30% 阈值抓不到任何真实回归，中间没有可用区间。

改用 ADR 009 Q20 已定的 `--stats` 计数器，取其中**确定性**的那些，记录基线并要求**精确相等**：

| 计数器 | 捕获什么 |
| --- | --- |
| 编译期求值步数 | eval 复杂度回归、意外的重复求值 |
| 单态化实例数 | 泛型实例爆炸 |
| AST 节点数 / 生成指令数 | 前端膨胀、降级膨胀 |

表中的计数器都是 ADR 009 Q20 已定的。**内存行为回归没有对应计数器，本 ADR 不补。** 新增 `--stats` 计数器属 ADR 009 的范围，在这里顺手加一行会造出一个没有任何 ADR 定义其语义的门——正是本轮反复驳回的那种判据。若将来需要，走 ADR 009 的修订。

这些数字与硬件、负载、温度无关，所以判据是相等而非区间。基线签入仓库；数字变化时**在同一次提交里更新基线**，diff 里能看到「这次改动让单态化实例从 412 变成 1180」——这比任何百分比告警都直接。

墙钟时间仍然记录（`--time-passes`），但**只作参考不作门**。它用于人工观察趋势，不产生失败。

ADR 009 已定 `--stats` 内部为键值对集合而非硬编码打印字符串，这让基线比对是结构化比对而非文本 diff。

#### 基准语料就是三类目标程序（Q8）

`docs/spec/01-overview.md` 已把 Kore 的目标锁定为三类程序：自举编译器、操作系统内核、虚拟机/解释器。基准语料就是它们，不另造微基准套件：

| 语料 | 压什么 |
| --- | --- |
| 编译器自身 | 大规模真实代码：模块解析、trait、泛型、eval |
| freestanding 内核骨架 | `bare/` 路径、`vol`、内联汇编、零运行时 |
| 字节码 VM / 解释器 | 分派循环、`jmp` 尾调用、指针密集访问 |

理由：微基准会把优化引向不重要的方向，而这三类程序的性能特征就是语言宣称要服务的性能特征。语料同时是**功能测试**——它们必须先能正确运行，才谈得上计时。

**LLVM 留作标尺，不作门。** 与 clang/LLVM 比对生成代码质量是有价值的观察，但不能设成「自举后端产物不得慢于 clang 的 N 倍」这类门：年轻的自举后端必然在很长时间内达不到任何有意义的比值，设了就是原则 2 说的那种会被绕过的门。而且 ADR 007 定了 `llvm/` 在自举后归档，把门绑在一个计划移除的组件上，门的寿命短于项目。

**差分测试（同一程序在 LLVM 后端与自举后端产出行为比对）不作为独立策略层。** 它的有效期只到 `llvm/` 归档为止，而它要求的基础设施（两套后端同时可用、行为等价性定义）成本不低。Q13 的矩阵覆盖以更低成本覆盖同一风险。

### 5. 主动找错（Q9–Q11）

#### 变异 fuzzing（Q9）

fuzzing 的输入**由已有用例变异得来**，不做随机程序生成：删记号、替换记号、复制块、改字面量值、截断文件。种子就是 `tests/` 全体。

判据只有一条：**编译器不得崩溃、不得 ICE、不得挂起**。变异后的程序编译失败是完全正常的结果，不要求它编译成功。这让 oracle 免费——不需要知道正确答案是什么，只需要知道「不该是 ICE」。ADR 009 Q15 已定 ICE 的表现形式，所以检测是精确的而非启发式的。

**不做覆盖引导 fuzzing。** 覆盖引导需要对被测编译器插桩。自举前可以借宿主工具链（stage0 是 Rust），自举后就要求 Kore 自己提供插桩能力——即一个语言特性。用测试策略去驱动语言特性的取舍是本末倒置，违背约束 1。

**不做语法定向的随机程序生成。** 它拖进三样东西：种子管理、失败最小化、以及「什么是良构程序」的模型。第三样是类型检查器的重述（见 Q6）。变异 fuzzing 用已有用例的良构性作为起点，绕开了这个模型。

#### 固定模式毒化未初始化内存（Q10）

调试构建下，未初始化的栈槽与堆分配用**固定模式**填充（未初始化 `0xAA`，已释放 `0xDD`），而非留作真实垃圾或填零。

填零是最坏选择：它让「读未初始化内存」这个 bug 表现为读到 0，而 0 恰好是很多情况下的正确答案，于是 bug 沉默。留作真实垃圾则让 bug 的表现依赖上一次栈使用，即依赖运气与调用顺序——今天复现明天不复现。

固定模式把它变成**总可复现**：`0xAAAAAAAA` 作为指针必定段错误、作为长度必定越界、作为标签必定不匹配任何变体。这是原则 1 在内存维度的同一个动作。

选这条路还因为约束 2：valgrind 与 ASan 在 Termux 上不可靠，而毒化是**编译器自己实现的**，不依赖任何外部工具，在 `bare/` 目标上同样可用——那里根本没有 sanitizer 可言。

#### 变异测试度量断言敏感度（Q11）

覆盖率说明代码被执行过，不说明**断言会不会因为它出错而失败**。度量后者的手段是变异测试：往编译器源码里注入变异（改比较方向、改常量、删语句），看有多少变异被测试套件抓住。逃逸的变异指向弱断言。

同时需要一条独立的机械检查：**红→绿是不对称的**。测试从绿变红有自然告警（失败），从红变绿没有——包括这些形态：

- 断言实际为空（如比对了两个相同的常量）
- 用例引用了已不存在的错误码（见 Q13 的双向检查）
- 用例不属于任何层，从未被运行（见 Q12 的孤儿检出）

这三类都表现为「永久绿」。它们必须被专门检出，因为没有任何自然事件会让它们变红。

### 6. 分层与预算（Q12）

分层由**时间预算**定义，不由 CI 产品定义（约束 3）。

| 层 | 预算 | 内容 |
| --- | --- | --- |
| **第一层** | ≤ 60 秒（参考移动设备） | 单元用例、诊断注解用例、双实现一致性、确定性便宜代理 |
| **第二层** | ≤ 15 分钟 | 全量集成、全后端矩阵、QEMU user-mode、基准语料功能验证与计数器比对 |
| **深度层** | 无上限，人工或里程碑触发 | stage2 == stage3 完整不动点、QEMU system-mode（`bare/`）、变异 fuzzing、变异测试 |

三条约束：

1. **预算是 ADR 里的数字。** 没有数字，分层只是命名——每条新用例都想要立即反馈，没人会主动把用例降级，第一层于是单调膨胀直到没人跑它。预算的执行方式是告警而非失败。把它做成硬门会让热降频直接判测试失败，于是门被调宽或被关掉；做成告警则超预算的信号仍然每次都出现，而处理它的动作是**重新分层**，不是改阈值。
2. **层归属声明在测试树里**，不在 CI 配置里。每个 `tests/` 子目录放一个 `LAYER` 文件声明所属层，子目录继承父目录声明除非自己覆盖。这样本地与远端不会分叉，且**`tests/` 下未被任何声明覆盖的用例可机械检出**——按 Q11，永不被运行的用例是空断言的极端形态。

   编译器树内的 `*_test.kore`（ADR 007 定为与实现同目录）不走 `LAYER` 文件：它们**按规则恒属第一层**——单文件、单进程、不涉 QEMU，成本天然落在第一层预算内。因此那些目录既不需要也不允许放 `LAYER` 文件，孤儿检出只对 `tests/` 生效，不会把每个实现目录都报成孤儿。
3. **确定性拆成两半。** 完整不动点需要三次编译器构建，在本硬件上不可能每次提交都做；但若只放深度层，每一步 bisect 都要三次构建，于是没人 bisect。解法是**便宜代理**进第一层：同一文件编译两次比对字节，成本约单文件编译的 2 倍，覆盖非确定性的主要来源（哈希迭代序、绝对路径泄漏、时间戳嵌入、并行合并序）。完整 stage2 == stage3 留深度层。

单层方案不可行：单层的速度等于其最慢成员的速度，即 QEMU system-mode 加三次构建。**不被运行的套件比没有套件更坏**，因为它提供假信心。两层方案容不下 Q9 的 fuzzing 与 Q11 的变异测试——这两者没有自然终点，无法住在一个必须终止的层里。

### 7. 覆盖判据（Q13）

覆盖有两维，都**机械生成**，都以**清单**呈现而非门。

#### 错误码覆盖，双向

编译器枚举自己的错误码集合（ADR 009 Q24 已定错误码登记表是唯一真相来源，且带 `active|retired` 状态），与测试树里 `--~ E####` 注解集合比对：

| 方向 | 含义 | 处理 |
| --- | --- | --- |
| 编译器有、测试树无 | 缺口——这条诊断从未被触发过 | 列入清单 |
| 测试树引用、编译器不存在 | 死注解——用例在等一个永不出现的错误码 | **直接报错** |

两个方向不对称是有意的。缺口是「还没写」，是待办；死注解是 Q11 的「永久绿」形态之一：注解引用了被 retire 或改号的错误码，双向匹配会因为编译器也不产出它而恰好通过。ADR 009 已定错误码不复用不改号，正是为了让这个检查是精确的。

#### 语法构造矩阵

AST 节点种类 × 后端（`llvm` / `x86_64` / `aarch64` / `bare`）。每格的内容是「至少一个用例在该后端上覆盖该节点」。

行的枚举**以编译器导出的节点种类集合为准**，不以任何文档里的数字为准。ADR 001 出现过两个数：附录「AST 节点分类统计」表的「总计 25+」不含基础节点（`Literal`、`Ident`、`Block` 等），后果一节的「约 30+ 种」含。二者不矛盾，但也都不是权威——权威是编译器自己的枚举，否则矩阵会随文档漂移。按含基础节点计，满格在 120 格量级。

选 AST 节点种类作为行，是因为 ADR 001 刻意把大量构造**保留为语义层节点**而非脱糖（`Pipe`、`ParallelAssign`、`Defer`、`?`/`@` 各三种形态都是独立节点）。每个保留的节点都是一条独立的降级路径，而降级路径正是「在某后端上错了」的发生地。若当初选了激进脱糖，这一维的价值会小得多。

```
                llvm   x86_64  aarch64  bare
Branch(union)     ✓       ✓       ✓       ✓
Loop(infinite)    ✓       ✓       ·       ·
Asm               ✓       ·       ·       ✓
TailCall(jmp)     ✓       ✓       ✓       ·
```

这一维替代了 Q8 驳回的差分测试：矩阵以更低成本覆盖同一风险（「某构造在某后端上降级错了」），且不需要两套后端同时可用，所以在 `llvm/` 归档后依然有效。

#### 清单不是门

矩阵与缺口清单按后端分组排序输出，**人决定补哪个**。不设百分比阈值。

理由是原则 4：行/分支覆盖率阈值一旦成为门，最省力的达标方式是写执行代码但不断言的用例——它同时污染覆盖率信号与测试套件。Q11 已定断言强度的度量手段是变异测试，覆盖率不承担这个职责，因此也不该被赋予门的权力。

**不用行覆盖或分支覆盖。** 除阈值问题外，还有约束 1：自举后取得覆盖率需要 Kore 自己提供插桩，与 Q9 驳回覆盖引导 fuzzing 同一个理由。

**不用类型规则组合覆盖。** 组合数取决于规则怎么切分，切分方式一变，数字就变——不稳定的信号不是信号。

### 8. 增长与里程碑（Q14）

结构需要动力学，否则十三轮的结论会变成一份无人维护的文档。两条增长规则加四道里程碑门。

#### 每个修复带一个回归用例，且先红后绿

修 bug 时必须留下用例，并且**记录它在修复前的失败形态**（诊断输出、退出码、或 ICE 消息）。

先红后绿不是仪式。一个未曾变红的回归用例无法证明它测的是被修的那个 bug——它可能因为别的原因绿，此后永远绿。这正是 Q11 列出的第一类「永久绿」。记录失败形态让这个证明留在树里，而非只存在于写用例时的一瞬间。

#### 里程碑门

判据写在 ADR 里，与 ADR 007 的 Phase 划分对齐：

| 里程碑 | 门 |
| --- | --- |
| **stage1 完成** | 第一层全绿；错误码覆盖无缺口；矩阵 `llvm` 列无缺口（其余列允许空白） |
| **stage2 完成** | 加：第二层全绿；且第一层与第二层在 stage2 自身下重跑一遍全绿 |
| **stage3 完成** | 加：矩阵自举后端列（`x86_64` / `aarch64`）无缺口；stage2 == stage3 字节相等；`llvm/` 可归档 |
| **`bare/` 完成** | 加：`test_exit` 通道可用；QEMU system-mode 层全绿 |

门是递增的，每一道包含前一道。矩阵列的推进顺序对应后端的实现顺序，所以「其余列允许空白」不是宽容而是时序事实——stage1 阶段自举后端还不存在。

递增靠**层**而非靠点名单条判据：便宜代理与双实现一致性族按 Q12 都住在第一层，stage1 门已要求第一层全绿，再在 stage2 门上点它们的名只是重复。stage2 门真正新增的是两件事——第二层（全后端矩阵、QEMU user-mode、基准语料）首次挂到门上，以及**同一批测试在 stage2 自身下重跑**：stage2 是第一个由 Kore 编译器编译出的 Kore 编译器，此前所有绿色都是 stage0/stage1 路径的绿色。

**不设用例退役机制。** 判断一条用例是否被另一条覆盖，需要证明断言强度的包含关系，而 Q11 已承认只有变异测试能近似度量断言强度。退役机制会以「这条看起来重复」为由删掉唯一抓住某个变异的用例。测试树增长带来的成本由分层预算（Q12）承担，不由删用例承担。

## 后果

### 正面

1. **判据全部可机械求值。** 双向注解匹配、计数器相等、字节相等、缺口清单、孤儿检出——没有一条需要人判断「这个差异可以接受吗」。
2. **自举有了可宣布完成的时刻。** Q4 修正了不动点位置，Q14 把它挂在 stage3 门上。
3. **对开发机的环境限制免疫。** 没有任何**正确性判据**依赖墙钟、`perf_event_open`、valgrind 或 ASan（约束 2）。毒化与计数器都由编译器自己实现。层预算（Q12）确实读墙钟，但它是编排告警而非门——超出只触发重新分层的提示，不判用例失败。
4. **判据不依赖 CI 产品。** 层归属与预算都在树里（约束 3），引入 git 与 CI 时不需要重新定义任何判据。
5. **双实现分歧有专门的测试族。** eval 与 codegen 的不一致是自举项目里最难自然暴露的一类 bug，Q6 让它有固定入口。

### 负面

1. **两个新注解记号，且校验责任不在同一侧。** `--~` 只有 runner 认识，编译器眼里是注释，拼写错误逃过编译器，要靠 runner 侧的语法校验兜底。`--=` 相反，编译器必须认识它才能在 pass 检查点上验证——这意味着契约断言的词法与语义进入了编译器本体，是一处为测试而存在的产出面。
2. **计数器基线要随功能改动更新。** 每次有意的优化或重构都会产生基线 diff，评审时需要判断数字变化是否合预期，这个判断无法机械化。
3. **矩阵与错误码清单需要编译器提供枚举接口。** 编译器要能导出自己的 AST 节点种类与错误码集合，这是为测试而存在的产出面。
4. **深度层可能长期不被运行。** 无上限的层没有自然触发点，Q14 的里程碑门是唯一的强制点；里程碑之间它依赖人的自觉。
5. **`test_exit` 是目标特定设施。** 尽管压缩到一个函数，它仍然意味着每个新的 `bare/` 平台都要实现一次关机序列才能跑测试。

### 取舍权衡

本轮反复出现同一个取舍：**在「宽松但真实的判据」与「严格但会被绕过的判据」之间选前者**。墙钟阈值（Q7）、clang 比值上限（Q8）、覆盖率阈值（Q13）三处都是后者，全部驳回——它们的共同点是数字会因噪声或平台而变，于是阈值只能放宽到无意义，或被反复调整直到不再报警。

Q4 不属于这个取舍，它是另一类错误：**判据写错了位置**。stage1 == stage2 不是「太严」，而是**不可满足**——stage1 的二进制由 stage0 经 LLVM 后端产出，stage2 由 stage1 经自举后端产出，两个不同的编译器没有理由产出相同字节。修正后的 stage2 == stage3 反而**更严**（逐字节，无容差）。区分这两类很重要：噪声阈值应当放弃，位置错误应当纠正而非放宽。

代价是缺口不会自动阻断——错误码清单里的空行、矩阵里的空格，都需要人看一眼并决定。换来的是每一次红色都是真实的失败，从而红色值得被响应。这是原则 2 的直接后果：一个被忽略的门在被忽略期间提供的是假信心，而假信心比没有信心更贵。

第二个取舍是**放弃统计手段，改用确定性手段**：拒绝随机程序生成（Q6、Q9）、拒绝覆盖引导（Q9、Q13）、拒绝真实垃圾内存（Q10）。这三处放弃的都是「更强但结果不可复现」的技术，换来「更弱但每次都一样」。对一个开发机会热降频、且最终产物必须字节可复现的项目，这个方向是被环境和目标共同决定的。

- [ ] 外部 runner 遍历两个根：`tests/`（按 `LAYER` 文件确定层归属，无声明覆盖的用例报孤儿错误）与编译器树内的 `*_test.kore`（按规则恒属第一层，不读 `LAYER`，出现 `LAYER` 文件报错）
- [ ] runner 解析 `--~ E#### <文本>` 注解，与诊断做双向匹配（缺失与多余都失败）
- [ ] runner 校验 `--~` 注解自身语法，拼写错误报错而非静默忽略
- [ ] 词法器识别 `--=` 并与 `--` / `---` / `--!` / `--~` 区分（第三字符消歧）
- [ ] `--= tailcall <name>` 检查点：验证 `jmp` 降级为跳转而非调用
- [ ] `--= volatile-load <type>` / `--= volatile-store <type>` 检查点：验证 `vol` 访问未被合并或消除
- [ ] `--=` 仅在其后紧跟空白时是契约断言；`--===` 之类的分隔线按普通行注释处理，不报未识别断言种类
- [ ] 无法识别的 `--=` 断言种类报错，不静默通过
- [ ] 结构化诊断比对走 ADR 009 已定的 `--error-format=json`，runner 解析字段；不新增 `--emit` 阶段
- [ ] `bare/` 提供 `test_exit(code)` 内置：x86_64 走 ISA debug-exit，aarch64 走 semihosting/PSCI
- [ ] 用例结果只经退出码上报，runner 不比对 stdout

- [ ] `--stats` 确定性计数器基线签入仓库，比对为精确相等；基线更新与功能改动同提交
- [ ] `--time-passes` 仅记录不设门
- [ ] 基准语料三份：编译器自身、freestanding 内核骨架、字节码 VM；先验证功能再计时

- [ ] 变异 fuzzing：以 `tests/` 为种子，判据为不崩溃、不 ICE、不挂起
- [ ] 变异测试：向编译器源码注入变异，报告逃逸变异
- [ ] 空断言检出：比对两个相同常量之类的恒真断言报错，不计为通过
